# 🚦 배포 절차 (2026-07-19 사장님 지시 — 예외 없음)

모든 라이브 수정은 아래 8단계를 **순서대로 전부** 거친다. 하나라도 건너뛰면 배포 금지.
"완료" 보고는 8단계가 끝난 뒤에만 한다.

| # | 단계 | 하는 일 | 통과 기준 |
|---|------|---------|-----------|
| 1 | **재현 테스트** | 버그면 먼저 `scripts/test-*.js` 에 재현 시나리오 작성 — 구버전 코드로 ❌ 재현되는 것 확인 | 버그가 테스트로 재현됨 |
| 2 | **수정** | 코드 수정 + BUST 마커 갱신 | — |
| 3 | **재확인** | `node scripts/release.js pre` — 변경 파일 전체 문법 검사 + 회귀 테스트 전부 실행 | 🎉 게이트 통과 |
| 4 | **구동** | 브라우저(Browser pane)로 해당 페이지 열어 로딩 콘솔 에러 0 확인 (로그인 게이트 전 구간) | 콘솔 에러 없음 |
| 5 | **마지막 확인** | `git diff` 전체 리뷰 — 의도한 변경만 있는지, BUST 갱신했는지 | 이상 없음 |
| 6 | **배포** | `git fetch` → 필요 시 rebase → `git push` | push 성공 |
| 7 | **배포 후 확인** | `node scripts/release.js post 파일=새BUST [파일!=제거한구코드]` — 라이브에서 직접 내려받아 확인 | 🎉 검증 통과 |
| 8 | **최종 완료** | 테스트 결과 + 라이브 검증 결과를 **첨부해서** 보고. 검증 없는 "고쳤다" 보고 금지 | — |

## 원칙

- **한 번에 하나** — 수정 하나를 8단계 끝까지 끝낸 뒤 다음 수정 시작. 연속 배포 금지.
- 순서/타이밍/상태 로직(단계식 로드, 캐시, 실시간 이벤트)은 반드시 **도착 순서 시나리오 전부**를 테스트에 포함 (예: `test-chat-order.js` 의 6종).
- 회귀 테스트는 지우지 않는다 — 같은 버그의 재발 방어선.
- 배포 후 각 기기 반영은 "사용 중 강제 리로드 금지" 규칙 때문에 한가할 때 자동 적용됨 — 즉시 확인이 필요하면 새로고침 1회 안내.

## 예시

```
node scripts/release.js pre                       # 변경된 파일 자동 감지
node scripts/release.js pre chat.html             # 특정 파일 지정
node scripts/release.js post chat.html=chat_2026_07_19_order_fix chat.html!=__roomOrderSeq
```
